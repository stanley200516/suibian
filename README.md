# 隨便啦：吃什麼・去哪玩

不知道吃什麼、放假不知道去哪？設定好條件，抽一個就對了。

- **兩種模式**：🍜 吃什麼／🏞️ 去哪玩（各自記住上次的條件）
- **出發點**：目前位置（GPS），或輸入地點
- **交通方式**：走路、腳踏車、機車、開車、大眾運輸
- **時間上限**：吃飯 5–60 分鐘、出去玩 15 分鐘–3 小時
- **營業時間**：現在營業中／指定出發時間／不限。用「抵達時間」判斷，而且抵達後還要營業夠久（吃飯 30 分鐘、出去玩 90 分鐘），不會抽到快打烊的店
- **類型與評分**：可複選料理／景點類型，設定 Google 評分門檻
- **抽完之後**：一鍵 Google 地圖導航（自動帶入交通方式）、分享給朋友、再抽一次、「不要這間」排除
- **最近抽過**：會盡量避開最近抽過的 5 個
- **三種語言**：繁體中文、English、日本語，依手機語言自動切換，也可以在設定裡手動選
- **依地區調整**：依出發點自動判斷台灣／日本／其他地區，換成當地的交通方式和料理類型（例如台灣有機車、日本有拉麵和居酒屋、其他地區有墨西哥菜）
- **在地化格式**：距離單位（公里／英里）、12／24 小時制、星期寫法都依語言和地區調整
- **PWA**：可加到手機主畫面，像 App 一樣全螢幕開啟

沒有 API key 時會使用 **OpenStreetMap 的免費資料**：店家都是真的，打開就能用，只是資料比 Google 少（見下方「資料來源」）。

## 快速開始

需要 Node.js 18 以上，不用安裝任何套件。

```bash
npm run dev
```

打開 http://localhost:5173 。

```bash
npm test
```

## 資料來源

| | OpenStreetMap（預設） | Google Places（填入 key 後） |
|---|---|---|
| 費用 | 免費，不用申請 | 要綁信用卡，每月有免費額度 |
| 店家 | 真實店家，市區很齊全 | 最齊全 |
| 營業時間 | 只有部分店家有（新宿站周邊約 1/4） | 大部分都有 |
| 評分、照片 | 沒有（評分條件會自動隱藏） | 有 |
| 穩定度 | 免費伺服器偶爾過載，會變慢 | 穩定 |

OpenStreetMap 的搜尋方式：

1. 先用 **Overpass API**，一次可拿到範圍內幾百個地點。
2. Overpass 失敗、逾時（12 秒）或回應不完整時，改用 **Nominatim**。每種類型最多 40 個地點，每次查詢間隔 1 秒以上（遵守 Nominatim 使用規範），之後 5 分鐘內都直接用 Nominatim。
3. 吃飯的範圍超過 3 公里、出去玩超過 30 公里時，隨機取範圍內的一塊來查，避免查詢太重。

資料 © OpenStreetMap 貢獻者，採用 [ODbL](https://www.openstreetmap.org/copyright) 授權，結果畫面有標示來源。

## 申請 Google Maps API key

1. 到 [Google Cloud Console](https://console.cloud.google.com/) 建立專案，並設定帳單（需要綁信用卡）。
2. 「API 和服務」→「程式庫」，啟用這兩個 API：
   - **Maps JavaScript API**
   - **Places API (New)**（注意不是舊版的 Places API）
3. 「API 和服務」→「憑證」→「建立憑證」→「API 金鑰」，然後編輯這把 key：
   - **應用程式限制**：選「網站」，加入 `http://localhost:5173/*` 和你部署後的網址（例如 `https://你的帳號.github.io/*`）
   - **API 限制**：只勾 Maps JavaScript API 與 Places API (New)
4. 建議到「帳單」→「預算與快訊」設定預算警示，避免意外費用。
5. 把 key 貼到 app 右上角的「設定」，或填進 `app-config.js`（部署給朋友用時，大家就不用自己輸入）。

### 費用

- 每次用**新的條件**抽選，會呼叫 3 次 Nearby Search（為了湊出更多樣的候選）。因為要拿營業時間欄位，屬於計價較高的等級。
- 同一組條件 10 分鐘內「再抽一次」會用快取，不會再呼叫 API。
- 抽中的地點會載入 1 張照片（Place Photos，另外計價）。
- Google 每個計價項目每月都有免費額度，個人使用通常在額度內，但請以 [Google Maps Platform 官方價目表](https://mapsplatform.google.com/pricing/) 為準。

## 部署到手機上用

手機瀏覽器只有在 **HTTPS** 網址下才能使用定位，所以要部署到網路上。整個資料夾都是靜態檔案，不需要建置，直接上傳即可：

- **GitHub Pages**：推到 GitHub repo →「Settings」→「Pages」→ 選 branch
- **Netlify** / **Cloudflare Pages**：把資料夾拖進去就好

部署後記得把網址加進 API key 的「網站」限制。

**加到主畫面**：iPhone 用 Safari 開啟 → 分享 →「加入主畫面」；Android 用 Chrome 開啟 → 選單 →「安裝應用程式」。

## 運作方式

1. 依交通方式與時間上限，估算可到達的半徑（直線距離 × 繞路係數 ÷ 速度 + 固定耗時，例如機車停車、等車）。
2. 在半徑內搜尋 3 輪（熱門排序、距離排序、隨機子區域），合併成候選池。Google 每輪最多回傳 20 筆。
3. 依評分、評論數、估計交通時間、抵達時是否營業來篩選。
4. 從符合條件的候選中均勻隨機抽一個，盡量避開最近抽過的。

速度與係數都在 `js/regions.js`，每個地區各自一組，可以依經驗調整。

「指定時間」視為**目的地當地的時間**：人在東京規劃紐約行程時，輸入 10:00 就是紐約的 10:00。

## 多語系與地區

### 語言

- 字典在 `js/locales/`（`zh-TW.js`、`en.js`、`ja.js`），每個 key 三種語言都要有，測試會檢查。
- 日期、時間、數字用瀏覽器內建的 `Intl` 格式化，不用自己寫格式。
- Google 回傳的店名、類型名稱也會跟著介面語言。
- App 名稱目前是「隨便啦」／「Whatever」／「なんでもいい」，在各語系檔的 `app.name` 修改。`manifest.webmanifest`（加到主畫面時的名稱）只能有一種語言，目前是中文。

**新增語言**：在 `js/locales/` 複製一份 `en.js` 翻譯，然後在 `js/i18n.js` 的 `LANGS` 和 `detectLang` 加上它；OpenStreetMap 的類型名稱在 `js/providers/osm.js` 的 `CUISINE_LABELS`、`TAG_LABELS`。

### 地區

| 地區 | 判斷方式 | 交通方式 | 料理類型特色 |
|---|---|---|---|
| 台灣 | 出發點在台灣本島、澎湖、金門、馬祖 | 走路、腳踏車、機車、開車、大眾運輸 | 中式・台式、燒肉・海鮮 |
| 日本 | 出發點在日本主要島嶼、沖繩 | 走路、腳踏車、開車、電車・巴士（較快） | 拉麵、壽司、燒肉、居酒屋 |
| 其他地區 | 以上都不是 | 走路、腳踏車、開車（較快）、大眾運輸（較慢） | 美式、墨西哥、印度、中東 |

- 還沒定位時先用手機時區猜；設定裡也可以手動指定地區。
- Google 的機車導航只在部分亞洲國家提供，所以只有台灣有機車選項。

**新增地區**：在 `js/regions.js` 的 `REGIONS` 加一組設定、在 `BOUNDS` 加經緯度範圍，再到三個語系檔加 `region.<代碼>`。

## 已知限制

- OpenStreetMap 改用 Nominatim 備援時，每種類型最多 40 個地點，選特定料理（例如拉麵）時可能找不到；Overpass 恢復後就會正常。
- OpenStreetMap 的營業時間只支援常見寫法，看不懂的（月份、日出日落等）當作「沒有資料」。

- **交通時間是估算的**，不是實際路線時間；大眾運輸的誤差最大。實際時間請以導航為準。
- 候選池大約 20–60 個地點，不是半徑內的所有店家。
- 台灣很多小吃店在 Google 上只被標成「餐廳」，選特定料理類型（例如「中式・台式」）時會漏掉這些店，選「都可以」最完整。
- 地區是用粗略的經緯度範圍判斷，邊界附近可能判斷錯（例如日本對馬會被當成其他地區），可以在設定裡手動指定。
- Google 地圖在某些國家不好用：中國大陸連不上；韓國的 Google 地圖不提供開車和步行導航。

## 專案結構

```
index.html              介面
styles.css              樣式（支援深色模式）
app-config.js           部署時可預先填入 API key
manifest.webmanifest    PWA 設定
sw.js                   Service worker（離線時可開啟）
js/
  app.js                畫面與流程
  config.js             時間範圍、搜尋輪次等與地區無關的設定
  regions.js            各地區的交通方式、料理／景點類型、地區判斷
  i18n.js               語言偵測、翻譯、距離與時間格式化
  locales/              繁中、英文、日文字典
  geo.js                距離、交通時間估算
  hours.js              營業時間判斷
  picker.js             篩選與隨機抽選
  storage.js            localStorage
  providers/google.js   Google Places 資料來源
  providers/osm.js      OpenStreetMap 資料來源（Overpass、Nominatim）
  providers/osm-hours.js OpenStreetMap 營業時間格式解析
tests/                  單元測試（node --test）
scripts/serve.mjs       開發用伺服器
```
